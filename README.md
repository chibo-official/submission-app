# 提出物管理システム ― 段階1〜3（①日次利用集計・②誤打伝票・④請求依頼票・⑤遅滞報告・⑥POS修正依頼・⑦現金管理票・⑧小口現金管理票・⑨金銭出納帳）

店舗が入力し、店舗責任者が承認し、経理部の受付箱に届くところまでを、8様式で実装しています。

## 構成
| ファイル | 役割 |
|---|---|
| index.html / app.js | 画面（店舗・承認・経理部の受付箱） |
| core.js | 期限・必須チェック・承認／差戻しのルール（画面とGASで同一） |
| config.js | **本番に切り替えるときの設定**（GASのURLを入れる） |
| api-demo.js | デモ用の裏側（ブラウザ内だけで動く。`config.js`が空のとき使用） |
| api-gas.js | 本番用（GASを呼ぶ） |
| gas/ | Google Apps Script側（Code.gs / Core.gs / Masters.gs） |
| test/ | 自動テスト（`node test/flow.test.js` ほか） |

## 本番への切り替え手順（約30分）
1. 新しいGoogleスプレッドシートを作る（例：「提出物管理_データ」）。
2. 拡張機能 → Apps Script を開き、`gas/` の3ファイル（Code.gs・Core.gs・Masters.gs）の内容を貼り付ける。
3. 関数 `setup` を1回実行（権限の許可が出ます）。シート6枚と、写真用のドライブフォルダが自動で作られます。
4. シート「設定」に、**経理部アクセスID**と**閲覧のみアクセスID**が自動で入ります。控えて、それぞれ経理部・AM／部長に伝えてください。
5. シート「担当者マスター」に、店舗ごとの担当者を入力する（担当者ID・店舗コード・氏名・店舗責任者にTRUE/FALSE・在籍）。店舗コードは書式が文字列になっています。
6. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」。実行：自分／アクセスできるユーザー：全員。発行されたURLをコピー。
7. `config.js` の `API_URL` にそのURLを貼り、GitHub Pagesに置く（`index.html`・`config.js`・`core.js`・`masters.js`・`api-gas.js`・`app.js`。`api-demo.js`は不要）。
8. 各店舗のタブレット・スマホで開き、ホーム画面に追加する。

## 注意
- ログインは店舗IDのみ（決定事項）です。店舗IDを知っていれば誰でも入れるため、URLと店舗IDは社外に出さない運用にしてください。
- 写真は、どの誤打区分でも3枚が必須です（誤打伝票・VOID伝票・訂正後伝票）。一括訂正伝票は任意の添付欄です。変更するときは`core.js`と`gas/Core.gs`の`CATEGORIES`を直します（シート「誤打区分マスター」は参照用で、動作には影響しません）。
- LINE WORKS通知は未接続です（`Code.gs`の`notify`が差込口）。
- 保管年数は電子帳簿保存法の確認後に決めます。

## ⑤遅滞報告・⑥POS修正依頼のルール（実装済み）
- ⑤：遅滞明細は最大4件（売上日＋金額、合計は自動）。遅滞理由は必須。提出期限の時刻は設けていません（入金した日に作成）。
- ⑥：報告区分は「10日の中間報告／20日の中間報告／月末」。日付から初期選択します（1〜3日は前月の月末、4〜10日は10日、11〜20日は20日、21日以降は当月の月末）。
- ⑥：1か月の上限は30行（引き継ぎ行を含む）。月末分の画面には、10日・20日で提出済み（承認待ち以降）の行を灰色で引き継いで表示します。同じ月・同じ区分の二重提出はできません。
- ⑥：提出期限は月末分のみ「翌月3日 9:00」。10日・20日の中間報告には時刻の期限を設けていません。
- 未実装：遅滞の自動判定（営業日カレンダーが必要）、⑤の預入予定の候補表示（現金管理票の提出後から）、LINE WORKS通知。

## 月末の現金管理（⑦⑧⑨）のルール（実装済み）
- 期限はすべて「翌月3日 9:00」。同じ月・同じ様式の二重提出はできません。
- ⑦：保管場所は店舗タイプで決まります（路面店・百貨店ほか＝レジ／ビル型＝ALSOK・1Fレジ・2Fレジ／本店型＝金庫・1Fレジ・2Fレジ）。金種の合計が「レジ基本元金A＋つり銭準備金B」と一致しないときは、理由が必須です。キッチンカー(800)は対象外です。
- ⑦の定額（基本元金A）は、シート「現金保管場所」で店舗ごとに設定します。現行様式の値がある道頓堀ビル店のみ登録済みで、定額が未設定の店舗は、店舗側がAを入力します。
- ⑧：合計（金種の小計＋預金残高）が、⑨の月末残高と一致すること。不一致、または⑨が未提出のときは理由が必須です。
- ⑨：前月繰越は前月の⑨の月末残高から自動で入り、一致しないと提出できません。1か月最大60行。領収書の写真は行ごとに任意で添付できます。
- 勘定科目（シート「勘定科目」）と摘要の定型文（シート「定型文」）は仮置きです。実際の運用に合わせて差し替えてください。
- 経理部の「月末の提出状況（全店）」で、全店の⑦⑧⑨の状況（未提出・期限超過を含む）と、3点そろった店舗数を確認できます。
- 未実装：⑨の経理使用欄、⑤遅滞報告の候補表示（⑦の預入予定から）、LINE WORKS通知。

## ④請求依頼票・①日次利用集計のルール（段階3・実装済み）
- ④：1件ずつ作成。必須は、入力者・ご利用日・会社名か宛名・郵便番号・宛先（住所）・お食事代金・レシートNo・レシートの写真（1枚）。電話・FAX・部署・役職・手数料・人数・備考は任意。期限はご利用日の翌月3日 9:00。店名と担当名は、ログイン店舗と入力者から自動で入ります。
- ①：店舗・月ごとに1件。**毎日**、その日の分を入力して「保存」します（経理部・閲覧のみのIDからは「入力中」として最新の内容が見えます）。月末に「月末の提出」を押し、店舗責任者が承認します。キー合計と内訳の合計が違う日が1日でもあれば、提出時に理由が必須です。期限は翌月3日 9:00（仮置き）。
- ①の項目は、シート「利用項目」で店舗ごとに変えられます。1行＝1項目で、「店舗コード（ALL＝全店共通）／区分（pt・cp・ar）／項番（0から）／項目名／使う（TRUE・FALSE）」。店舗コードを書いた行が、ALLの行より優先されます。提出後の伝票には、提出時の項目構成が残ります（あとで設定を変えても過去分は変わりません）。
- 経理部は、受付箱の伝票ごとに「Excelで保存」「PDFで保存（印刷）」、一覧は「一覧をExcelで保存」が使えます（閲覧のみのIDも可）。※ 試作版（Claudeの画面内）では、ダウンロードが制限されることがあります。本番の環境（GitHub Pages）で動作を確認してください。
- 責任者の承認用PIN（4けた）は、後回しにしています。
- 経理部の「月末の提出状況（全店）」に、①の列が加わりました（①⑦⑧⑨がそろった店舗数を表示）。
